# StreamRelay TV — تطبيق الأندرويد (مشغّل أصلي)

تطبيق مشاهدة أصلي (Kotlin + Jetpack Compose + Media3/ExoPlayer) يتصل بـ API اللوحة مباشرة.
يحلّ محل التطبيق القديم الذي كان مجرد WebView يفتح `/watch` — وهذا هو سبب «الدوران» الطويل
عند أصحاب الإشارة الضعيفة: المشغّل داخل WebView لا يمكن ضبطه ليبدأ بأدنى جودة.

## ماذا يفعل

| الميزة | التفاصيل |
|---|---|
| **يعمل داخل الشبكة أو خارجها** | يُكتب عنوان السيرفر مرة واحدة (IP محلي مثل `192.168.1.10` أو دومين عام مثل `tv.example.com`). كل روابط التشغيل تُعاد كتابتها على هذا العنوان، فلا يهم ما هو العنوان المضبوط في اللوحة. |
| **بحث تلقائي في الشبكة** | يفحص كل عناوين شبكة الواي-فاي الحالية (/24، منفذ 80 و8080) ويجد سيرفرات StreamRelay خلال ثوانٍ. |
| **إقلاع مثل يوتيوب** | تقدير سرعة ابتدائي 250 kbps → أول مقطع من 144p (≈50 KB) فتظهر الصورة خلال ثانية، ثم ترتفع الجودة تلقائياً بعد قياس السرعة الحقيقية. |
| **ثبات على الإشارة الضعيفة** | رفع الجودة بتحفّظ (0.65 من السرعة المقاسة) وخفضها بسرعة؛ مخزن حتى 60 ثانية؛ البدء بعد ثانية واحدة من المخزن؛ 20 ثانية خلف الحافة الحية. |
| **اختيار الجودة يدوياً** | زر «الجودة» في المشغّل: تلقائي / 720p / 480p / 240p / 144p (حسب سلّم القناة). |
| **قنوات On Demand** | ينتظر إقلاع القناة على السيرفر ويعرض رسالة الحالة، ويرسل نبضة مشاهدة كل 30 ثانية حتى لا تتوقف القناة أثناء المشاهدة. |
| **تعافٍ تلقائي** | عند انقطاع البث أو انتهاء الرابط يعيد طلب رابط التشغيل من اللوحة ويعيد التحضير بلا تدخّل (حتى 40 مرة). |
| **السابق/التالي والتشغيل التلقائي** | التنقّل بين قنوات القسم، وتشغيل الفيديو التالي تلقائياً في الأفلام. |
| **الحساب** | جلسة بتوكن مع تجديد تلقائي؛ إعادة دخول تلقائية عند انتهاء التوكن؛ رسالة واضحة عند الدخول من جهاز آخر أو انتهاء الاشتراك (تنبيه قبل 3 أيام). |

## واجهات API المستخدمة

`GET /api/health` (اكتشاف السيرفر) · `GET /api/branding` · `POST /api/auth/login` · `POST /api/auth/refresh` ·
`POST /api/auth/presence` · `GET /api/categories` · `GET /api/channels?limit=500` ·
`GET /api/channels/:id/playback-url` · `POST /api/channels/:id/pulse` (جديد في 2026.09.22-1) · `GET /api/img?u=`

## البناء (على سيرفر لينكس فيه Docker — لا يحتاج Android Studio)

```bash
# على جهازك:
tar czf app.tgz android-app            # بدون signing/ و build/
scp app.tgz build-on-server.sh root@SERVER:/opt/streamrelay-app/
scp android-app/signing/*  root@SERVER:/opt/streamrelay-app/signing/

# على السيرفر:
sudo bash /opt/streamrelay-app/build-on-server.sh
# الناتج: /opt/streamrelay-app/out/StreamRelay.apk
```

أول بناء ينزّل Gradle والمكتبات (~5–10 دقائق)، وما بعده ~2–3 دقائق.

### مفتاح التوقيع — لا تفقده

`android-app/signing/streamrelay-release.jks` + `signing.properties` (خارج git). أي نسخة مستقبلية يجب أن
تُوقَّع بنفس المفتاح وإلا رفض أندرويد التحديث فوق النسخة المثبّتة. احتفظ بنسخة في مكان آمن.

## النشر للعملاء

اللوحة تخدم الملف من `public/app/StreamRelay.apk` عبر `/api/app/download` (زر «تحميل تطبيق الأندرويد»
في صفحة دخول المشاهدين). سكربتا التثبيت/التحديث ينزّلانه من إصدار GitHub باسم `app-latest`،
فارفع الـAPK الجديد إلى ذلك الإصدار (أو انسخه يدوياً إلى `public/app/` على السيرفر).

الحزمة الجديدة `com.streamrelay.tv` مختلفة عن القديمة `com.streamrelay.viewer`، فتُثبَّت بجانبها؛
يمكن للعميل حذف القديمة بعد التأكد أن الجديدة تعمل.

## الأرقام المضبوطة (لمن يريد التعديل)

- `player/PlayerFactory.kt`: تقدير السرعة الابتدائي، عوامل رفع/خفض الجودة، أحجام المخزن، الإزاحة عن الحافة الحية.
- `Api.kt`: المهل الزمنية وإدارة التوكن.
- `LanScanner.kt`: المنافذ المفحوصة (80، 8080) والتوازي (48 اتصالاً).
